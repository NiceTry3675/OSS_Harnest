# 소설 창작 템플릿 로드맵

이 문서는 `new_template_make_art` 브랜치에서 개발할 소설 창작 템플릿의 작업 범위와 순서를
정의한다. Harnest 전체 제품 로드맵이나 현재 제품 계약을 바꾸는 문서가 아니다. 구현 결과가 실제
제품 정책이나 불변식을 바꿀 때만 `SPEC.md`와 루트 `ROADMAP.md`를 별도로 갱신한다.

## 목표와 범위

사용자가 승인한 인물·세계·사건의 약속을 지키면서, 인물이 선택과 변화로 입체적으로 드러나는
소설 한 편을 만든다. 단순히 문장을 길게 이어 붙이는 기능이 아니라 다음 두 실패를 반복 개선의
핵심 대상으로 삼는다.

- 분량이 늘수록 인물의 욕망·두려움·관계·말투가 평면화되거나 앞뒤가 달라지는 문제
- 세계 규칙, 시간 순서, 소유물, 지식 범위, 사건의 원인과 결과가 서로 모순되는 문제

첫 출시 범위는 **한 프로젝트에서 완결된 소설 한 편을 만들고 내려받는 흐름**이다. 연재 협업,
출판 편집·교정, 표지 생성, 삽화, 독자 반응 예측, 여러 권에 걸친 세계관 관리는 포함하지 않는다.
지원할 목표 분량과 장 수는 모델별 문맥·출력 한도와 비용 실측 뒤 확정한다.

## 1단계 — 유저 시나리오와 시스템 설계

구현 전에 사용자에게 무엇을 약속하고 어떤 상태를 동결할지 문서와 타입 초안으로 확정한다.

### 유저 시나리오

1. 사용자는 소설의 장르, 독자층, 시점, 문체 방향, 목표 분량과 직접 쓴 발상 또는 기존 초고를
   입력한다.
2. 사용자는 주요 인물마다 겉으로 원하는 것, 실제로 필요한 것, 두려움·결함, 숨기는 정보,
   중요한 관계, 시작 상태와 끝 상태를 정한다. AI가 초안을 제안할 수 있지만 사용자가 수정하고
   채택한 내용만 정본이 된다.
3. 사용자는 세계 규칙, 시간·장소, 반드시 일어날 사건, 피해야 할 전개와 표현을 정한다.
4. Harnest는 입력을 바탕으로 이야기 설계도(막·장·장면의 역할), 인물 아크, 정합성 명제와
   평가 질문 초안을 만든다. 사용자는 이를 검토·수정한다.
5. Harnest는 다음 내용을 승인 화면에 공개한다.
   - 인물·세계·사건 정본과 이야기 설계도의 지문
   - 구조·분량처럼 규칙으로 검사할 항목
   - 인물 입체성, 인물 아크, 설정·시간선 정합성, 인과성, 장면 기능, 문체를 판단할 기준
   - 개선용·중간 점검용·최종 확인용 평가 질문의 수와 사용 방식
   - 생성·채점 모델, 최대 호출 수, 예상 비용 범위와 알려진 한계
6. 사용자가 평가 구성을 승인하면 Harnest는 원샷 초고를 장 단위로 만들고 같은 절차로 기준선을
   기록한다. 기존 초고가 있으면 원샷 생성 대신 그 초고가 기준선이 된다.
7. 각 개선 라운드는 공개된 실패 근거를 바탕으로 한 번에 한 장 또는 연결된 소수 장면만 고친다.
   수정 전에는 대상, 의도, 보존해야 할 약속을 선언한다.
8. 구조·분량 gate를 통과하고, 비공개 중간 점검이 허용 범위에서 퇴보하지 않으며, 공개 종합
   점수가 엄격히 오른 후보만 채택한다. 동점과 설정 회귀가 있는 후보는 기존 원고를 유지한다.
9. 사용자는 관제실에서 현재 장, 수정 전략, 채택·기각 이유, 인물·정합성·서사 점수의 변화를 보고
   라운드가 끝나는 시점에 일시정지하거나 재개한다.
10. 종료 시 Harnest는 처음과 최종 원고를 동일한 최종 확인 질문으로 비교한다. 사용자는 최종
    원고와 이야기 바이블, 장별 개요, 승인된 평가 구성, 개선 기록을 내려받는다.

### 시스템 설계 초안

소설을 하나의 거대한 문자열로 매번 다시 쓰지 않는다. 템플릿 산출물은 구조화하되 독자가 받는
최종 결과는 자연스러운 원고 한 편으로 렌더한다.

```text
NovelProblem (사용자가 승인할 창작 계약)
├─ NovelBrief          장르·독자·시점·문체·목표 분량
├─ StoryBible          인물 카드·관계·세계 규칙·금지 사항
├─ NarrativePlan       막·장·장면의 목표와 인물 아크 경계
├─ ContinuityClaims    반드시 참이어야 하는 사실·시간·지식·인과 명제
└─ EvaluationProbes    공개 / 검증 가드 / 최종 확인 질문

NovelArtifact (라운드마다 체크포인트에 저장되는 후보)
├─ chapters[]          안정적인 id를 가진 장과 본문
├─ revisionSummary     이번 후보가 바꾼 범위와 의도
└─ evidenceIndex       평가용 근거 위치; 원고에서 다시 계산 가능해야 함
```

- `StoryBible`, `NarrativePlan`, `ContinuityClaims`, 평가 질문과 루브릭 버전의 내용 지문을
  Evaluation Pack의 `params`에 결속한다. 이 가운데 하나라도 바뀌면 재컴파일·시험관 검증·재승인이
  필요하다.
- `initial`은 장별 생성 결과를 조립해 원샷 원고를 만들고, `generate`는 선언한 대상 장면만 새로
  생성한 뒤 나머지 장을 그대로 복사해 후보를 만든다. 엔진에는 소설 전용 분기를 넣지 않는다.
- Generator에는 전체 정본, 현재 대상 장면, 인접 장 요약과 공개 평가 근거만 준다. 검증 가드의
  개별 질문·판정 사유와 최종 확인 점수는 전달하지 않는다.
- 전체 전문을 매 호출에 싣지 않도록 장별 요약과 연속성 원장을 사용하되, 요약은 원고에서 다시
  만들 수 있는 파생 데이터로 취급한다. 파생 데이터가 정본을 몰래 바꾸지 못하게 한다.
- 결정적 gate는 장 누락·중복, 구조화 출력 오류, 빈 장, 승인된 전체·장별 분량 범위처럼 코드로
  판정 가능한 항목만 맡는다. 인물성이나 설정 해석을 결정적이라고 가장하지 않는다.
- LLM 평가는 최소한 `인물 입체성`, `인물 아크`, `설정·시간선 정합성`, `사건 인과성`,
  `장면 기능`, `문체·시점 유지`를 분리해 기록한다. 가중치와 집계식은 승인 전에 공개한다.
- 설정과 아크 질문은 내용 지문에서 유도한 시드로 공개·검증 가드·최종 확인 세트에 고정 분할한다.
  정본 자체는 집필에 필요하므로 Generator에 공개하되, 비공개 질문과 그 점수에서 파생된 신호는
  숨긴다.
- 현재 계약의 `case_answering`만으로 근거 인용형 소설 평가가 충분한지 작은 실험으로 먼저
  확인한다. 충분하지 않으면 범용 `rubric_judge` 계약을 설계하고 SPEC·계약 테스트를 함께
  갱신한다. LLM 판정을 기존의 결정적 gate로 우회해 넣지 않는다.
- 장편 체크포인트가 브라우저 저장소와 결과 JSON의 현재 용량을 넘는지 측정한다. 저장 형식을
  바꿔야 한다면 소설 전용 예외 대신 모든 구조화 산출물이 쓸 수 있는 버전형 계약으로 확장한다.

### 1단계 완료 조건

- 신규 사용자와 기존 초고 보유 사용자의 화면별 여정, 취소·수정·재승인·재개 흐름이 문서화됨
- `NovelProblem`, `NovelArtifact`, 평가 질문, 점수 집계, 프롬프트별 정보 접근표의 타입 초안이 있음
- MVP 목표 분량, 장 수, 호출·토큰 예산, 저장 상한에 대한 실측 계획이 있음
- 다음 정책 결정이 기록됨: 기존 초고 처리, 이야기 설계도 승인 범위, 정합성 위반의 채택 규칙,
  사용자 직접 수정 후 재개 규칙

## 2단계 — 평가 프로토타입과 판정 계약 확정

- 짧은 기준 원고와 의도적으로 손상한 대조 원고를 만든다. 손상 유형은 인물 평면화, 동기 없는
  선택, 지식 범위 위반, 시간선 충돌, 소품 순간 이동, 복선 없는 해결, 시점·말투 이탈을 포함한다.
- 근거 인용형 평가가 각 손상을 안정적으로 구분하는지 모델별로 반복 측정한다. 평가자는 원고에
  없는 근거를 만들지 못하며, 찾지 못한 경우 명시적으로 실패해야 한다.
- 같은 원고 재채점의 흔들림, 그럴듯한 자기변호에 대한 아첨, 존재하지 않는 장면의 날조,
  길고 화려한 문장을 입체성으로 오인하는지를 시험관 배터리에 넣는다.
- 공개·가드·홀드아웃 질문이 같은 실패 유형과 주요 인물에 편중되지 않도록 층화 후 시드 분할한다.
- 점수 가중치, 가드 허용 오차, 최소 케이스 수, 재시도 정책과 호출 예산을 실측값으로 정한다.

완료 조건은 선택한 저지 모델이 승인 전 배터리를 통과하고, 계약 변경이 필요하면 타입·다이제스트·
저장 검증·회귀 테스트까지 함께 정의된 상태다.

## 3단계 — `templates/novel` 핵심 구현

- 질문 선언, 컴파일러, 타입, 프롬프트, 파서, scorer, 전략 선택기, 초기 생성기와 국소 수정기를
  독립 워크스페이스로 구현한다.
- 인물 카드는 특성 목록이 아니라 욕망↔두려움, 말↔행동, 자기인식↔타인의 인식처럼 장면에서
  드러나는 긴장을 포함한다. 평가는 형용사 언급 횟수가 아니라 선택·행동·대사·결과의 근거를 요구한다.
- 정합성 명제는 사실, 시간, 위치, 소유, 관계, 인물이 알 수 있는 정보, 원인→결과를 안정적인 id로
  관리한다. 장 수정 후 영향받는 인접 장을 계산해 평가 범위를 정한다.
- 파싱 실패는 조용히 부분 채점하지 않고 형식 수정 요청 1회 뒤 명시적으로 중단한다. 호출 예산을
  넘으면 체크포인트를 보존한다.
- 컴파일 순수성, 다이제스트 변화, 정보 비누출, 국소 수정의 비대상 장 보존, 구조 gate, strict
  scalar 채택, 가드 퇴보 기각, 일시정지·재개를 단위 테스트한다.

## 4단계 — 웹 관제실 통합

- `TemplateEntry` 등록만으로 템플릿 선택, 인터뷰, 승인, 실행, 결과 흐름을 연결한다. 페이지나
  루프 엔진에 `templateId === "novel"` 분기를 추가하지 않는다.
- 인터뷰에 인물 카드, 관계, 세계 규칙, 장별 설계도와 평가 질문 검토 UI가 필요하다면 기존
  `Question` 선언을 범용 필드로 확장한다.
- 실행 화면은 전체 원고보다 현재 수정 범위, 전략, 기준별 점수, 정합성 회귀 여부를 우선 보여준다.
  비공개 가드·홀드아웃의 질문과 추론 가능한 세부 신호는 노출하지 않는다.
- 결과 화면은 장 탐색이 가능한 원고 뷰, 인물 아크·정합성 요약, 처음/최종 비교와 한계를 제공한다.
  산출물은 최소 Markdown과 일반 텍스트로 내보내고 감사 기록 JSON과 구분한다.
- 긴 원고의 새로고침 복원, IndexedDB 체크포인트, 모바일/좁은 화면, 접근성과 시각 회귀를 검증한다.

## 5단계 — 실측과 튜닝

- 동일 입력으로 원샷과 반복 개선 결과를 만들고, 조건을 모르는 사람의 블라인드 평가로 인물
  입체성·설정 오류·전체 선호도를 비교한다.
- 자동 점수 상승뿐 아니라 사람 평가와의 상관, 가드가 막은 실제 회귀, 홀드아웃 변화, 라운드별
  비용·시간·토큰, 파싱 실패율을 기록한다.
- 단편·중편 후보 분량, 인물 수, 장 수와 입력 언어를 나누어 측정한다. 지원하지 못한 범위는 결과에
  명시하고 과장해 일반화하지 않는다.
- 실패 사례를 보고 프롬프트·루브릭·분할·예산을 바꾸면 Evaluation Pack 지문과 시험관 검증도
  함께 바뀌는지 확인한다. 원시 관측과 동결 프로토콜은 수정하지 않고 정정 기록만 덧붙인다.

출시 후보가 되려면 원샷 대비 자동 점수만 오른 것이 아니라, 블라인드 사람 평가에서 설정 오류가
줄고 인물 입체성 선호가 개선되며 비용 상한 안에서 완주할 수 있다는 근거가 필요하다.

## 6단계 — 출시 준비

- README의 현재 기능, SPEC의 현재 범위와 새 판정 불변식, 템플릿 한계, BYO 데이터 경로를 실제
  구현과 맞춘다.
- 타입 검사, 관련 단위 테스트, 전체 테스트와 프로덕션 빌드를 통과시킨다.
- 모델 연결 실패, 출력 잘림, 호출 예산 소진, 탭 종료, 저장 용량 부족, 다이제스트 불일치와
  홀드아웃 실패를 사용자에게 복구 가능한 상태로 보여준다.
- 개발용 예시와 모의 모델 경로를 제공하되, 모의 결과를 실제 창작 품질의 증거로 표시하지 않는다.
- 완료된 항목은 이 문서에서 제거하고 Git과 `experiments/`에 구현·실측 기록을 남긴다.

## 구현 전에 닫아야 할 결정

| 결정 | 기본 방향 | 확인 방법 |
|---|---|---|
| 첫 출시 분량 | 장 단위 국소 수정이 가능한 단편 또는 중편부터 시작 | 모델별 출력·문맥·비용 실측 |
| 기존 초고 | 선택 입력으로 받고 기준선으로 채점 | 초고 없음/있음 두 사용자 테스트 |
| 이야기 바이블 변경 | 승인 뒤 변경은 재컴파일·재승인 | 다이제스트 회귀 테스트 |
| 설정 위반 처리 | 공개 점수 + 비공개 가드 비퇴보를 기본으로 하되 절대 위반 정책은 별도 결정 | 손상 원고 실험과 오탐 측정 |
| 평가 방식 | 근거 인용형 케이스 평가 우선, 부족할 때만 범용 계약 확장 | 대조 원고 판별·안정성 실험 |
| 수정 단위 | 한 장 또는 연결된 소수 장면의 원자적 패치 | 비대상 장 동일성 테스트 |
| 사용자 직접 편집 | 새 기준선으로 재시작하거나 별도 승인 상태를 요구 | 체크포인트 귀속·감사 정책 설계 |
| 저장 방식 | 브라우저 우선, 원고 크기 실측 뒤 범용 버전형 확장 | IndexedDB·1 MiB 봉투 한계 측정 |
