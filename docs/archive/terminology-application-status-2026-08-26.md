| 상태 | 뜻 |
|---|---|
| **반영 완료** | 정한 용어가 현재 사용자 노출 화면의 해당 문맥에 적용됨 |
| **일부 반영** | 주요 화면에는 적용됐지만 다른 화면·문서 또는 세부 문구가 남아 있음 |

## 문안 적용 원칙

비개발자에게 익숙한 표현을 쓴다는 이유로 문장을 길게 늘이지 않는다.

1. 라벨·배지·버튼·목록 상태는 원문과 비슷한 길이를 유지한다.
2. 비유적이거나 전문적인 명사만 짧고 명확한 대표어로 교체한다.
3. 동작 설명은 처음 등장하거나 다음 행동을 안내해야 할 때만 한 번 제공한다.
4. 화면 제목이나 주변 문맥에서 이미 드러난 주체·대상은 반복하지 않는다.
5. 대표 용어를 문장에 기계적으로 끼우지 않는다. 과정은 `중간 점검`, 측정값은 `중간 점검 점수`, 짧은 실패 상태는 `중간 점검 점수 기준 미달`로 문맥에 맞게 구분한다.
6. 짧은 상태와 상세 설명을 분리한다. 목록에는 `중간 점검 점수 기준 미달`, 상세 기록에는 `새 개선안의 중간 점검 점수가 허용 범위보다 낮아 현재 결과물을 유지했습니다`라고 주체·판단 기준·결과를 적는다.

## 4. 아직 반영하지 않은 용어 묶음

아래 항목은 [`terminology-inventory.md`](../terminology-inventory.md)에 후보와 교체 방향이 있지만 이번 프런트 패치에는 포함하지 않았다.

| 남은 묶음 | 상태 | 남겨 둔 이유 또는 다음 작업 |
|---|---|---|
| 입력 자료 / 제약 조건 / AI 초안 / 근거 대목 | **미반영** | 입력 화면 전체 문장과 템플릿별 의미를 함께 검토해야 함 |

| 벤더 / 프로바이더 / 모의 모델 / 로컬 모델 | **미반영** | AI 연결 화면 전체의 정보 구조와 함께 정리해야 함 |

| JSON 내보내기 / 서버에 기록 / 문서 내려받기 | **미반영** | 저장 대상별 버튼명을 한 번에 정리하는 별도 패치가 필요함 |

| provenance / 결속 / 귀속 / 다이제스트 | **미반영** | 저장·복원 기술 설명과 핵심 문서를 함께 변경해야 함 |

| 패널 / 캘리브레이션 / Goodhart / 비정형 문제 등 문서 용어 | **미반영** | 프런트가 아닌 핵심 문서 교체 단계에서 처리 예정 |

## 6. 코드와 기능에서 변경하지 않은 것

이번 패치는 **사용자 노출 문구와 개발용 비교 화면만 변경**한다. 다음 항목은 바꾸지 않았다.

- 평가, 채점, 채택, 중간 점검과 최종 확인의 실제 실행 규칙
- `definitionDigest`의 범위와 재승인 조건
- 필수 조건 위반, 중간 점검, 종합 점수 개선에 따른 채택 순서
- 최종 확인 사례를 개선·채택·중단 판단에 사용하지 않는 정책
- `candidate`, `champion`, `guardScore`, `holdoutPolicy`, `checkpoint` 등 코드 식별자와 타입
- 화면 흐름, 입력 필드, API 요청, 저장 형식과 데이터 구조
- 홈 표어와 브랜드 문구

## 7. 검증 및 다음 결정

현재 패치에 대해 다음 검증을 완료했다.

- `npm run typecheck` 통과
- `npm run build` 통과
- 전체 Vitest 18개 파일, 210개 테스트 통과
- `git diff --check` 통과

다음 순서는 아래와 같다.

1. `/terminology-compare`에서 기존 문구와 변경 문구를 사용자와 비교한다.
2. 남은 1차 용어를 확정하거나 수정한다. `중간 점검`은 사용자 검토로 확정했다.
3. 승인된 프런트 패치만 커밋한다.
4. §4의 미반영 묶음을 작은 단위로 하나씩 적용한다.
5. 프런트 용어가 안정된 뒤 핵심 제품 문서에 같은 기준을 적용한다.
