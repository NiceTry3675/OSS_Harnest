# 노벨 템플릿 디자인

이 문서는 어느 정도 이야기와 설정을 준비한 사용자가 자신의 자료를 Harnest에 넣고, 설정을
정본화한 뒤 일관성과 인물성을 지키며 소설 한 편을 개선하는 템플릿의 중심 설계를 설명한다.
구현 순서와 미완료 범위는 [`novel-template-roadmap.md`](novel-template-roadmap.md)에서 관리한다.

## 대상 사용자와 문제

대상 사용자는 빈 입력창에 아이디어 한 줄만 넣는 사람이 아니다. 설정집, 시놉시스, 인물 노트,
부분 원고 또는 완성 초고 가운데 하나 이상을 가지고 있으며, 자신의 창작 의도를 유지한 채 AI의
도움을 받고 싶은 사람이다.

이 템플릿은 장문 생성에서 반복되는 두 문제를 우선 해결한다.

- 분량이 늘어날수록 인물의 욕망, 두려움, 관계, 말투와 지식 범위가 평면화되거나 앞뒤가 달라진다.
- 세계 규칙, 사건 순서, 위치, 소유물과 원인·결과가 서로 충돌한다.

AI는 사용자의 설정을 대신 결정하는 저자가 아니라, 사용자가 확정한 창작 계약 안에서 원고를
만들고 수정하는 실행자다.

## 전체 사용자 흐름

1. 사용자는 Markdown, 일반 텍스트, 텍스트 레이어가 있는 PDF 또는 DOCX 파일과 직접 입력한
   설명을 제출한다. 모든 추출은 브라우저 안에서 이루어진다.
2. Harnest는 문서 경계를 유지한 채 내용을 조각으로 나누고 작품 정보, 세계관, 등장인물,
   인물 관계, 사건, 시간선과 정본 후보를 분석한다.
3. 각 분석값은 원본 파일과 위치, 짧은 인용 근거를 가진다. 원문에 직접 적힌 사실과 AI가 추론한
   내용을 구분한다.
4. 서로 충돌하거나 여러 방식으로 해석할 수 있는 내용, 집필에 필요한 빈칸을 모아 사용자에게
   정본화 인터뷰를 진행한다.
5. 사용자는 사실 하나를 선택하는 것뿐 아니라 인물의 잘못된 믿음, 소문, 거짓말, 신뢰할 수 없는
   화자의 주장, 의도적인 미스터리 또는 아직 미정인 내용으로 분류할 수 있다.
6. 답변을 반영한 뒤 영향받은 부분을 다시 검사한다. 소설 생성에 필요한 필수 문제가 사라질 때까지
   관련 질문만 이어서 묻는다.
7. 사용자가 이야기 정본을 승인하면 그 내용 지문을 평가 구성에 결속한다. 정본이나 판정 절차가
   바뀌면 기존 승인과 체크포인트는 무효가 된다.
8. 기존 초고가 있으면 그 원고를 기준선으로 사용한다. 초고가 없으면 승인된 이야기 설계에 따라
   장별 원샷 원고를 만든다.
9. 개선 라운드는 문제를 고칠 장 또는 연결된 소수 장면과 보존할 설정을 먼저 선언하고 국소 수정한다.
10. 구조 gate, 비공개 검증 가드와 공개 평가를 통과하고 종합 점수가 엄격히 상승한 후보만 채택한다.
11. 종료 시 시작 원고와 최종 원고를 같은 최종 확인 질문으로 비교하고 원고, 이야기 정본과 감사
    기록을 각각 내려받는다.

## 분석 결과의 구조

분석 결과는 AI가 만든 요약문 하나가 아니라 이후 검증에 사용할 수 있는 구조화 데이터다. 최상위
영역은 다음과 같다.

- **출처 문서**: 파일명, 형식, 내용 지문, 페이지·제목·문단·행 단위 원문 조각
- **작품 정보**: 제목, 언어, 장르, 독자층, 전제, 주제, 시점, 시제, 분위기와 초고 상태
- **세계관**: 시대, 장소, 조직, 문화, 제도, 물건, 용어와 조건·결과·예외를 가진 세계 규칙
- **등장인물**: 이름과 별칭, 역할, 배경, 목표, 내적 필요, 두려움, 상처, 잘못된 믿음, 가치,
  모순되는 면, 행동 경계, 비밀, 말투, 지식 범위와 인물 아크
- **관계 그래프**: 등장인물 노드와 방향성 있는 다중 관계 간선, 사건 전후의 관계 상태 변화
- **사건과 시간선**: 배경 사건·본문 사건·계획 사건, 시간과 서술 순서, 장소, 참여자, 원인, 결과,
  상태 변화와 지식 변화
- **정본 명제**: 특정 시점에 누구 또는 무엇에 대해 참이어야 하는 검증 가능한 사실
- **분석 문제**: 모순, 모호성, 동일 개체 여부, 시간선 충돌, 인과 공백, 누락 정보와 의도적
  미스터리 후보

각 분석값에는 원문에 직접 쓰였는지 또는 추론인지, 사용자가 확인했는지, 어느 원문 조각을
근거로 삼았는지가 붙는다. 모델이 스스로 매긴 막연한 신뢰도 숫자는 정본의 근거로 쓰지 않는다.

## 인물 관계 그래프

인물 관계는 한 인물의 속성 안에 문자열로 넣지 않고 별도 속성 그래프로 관리한다. 같은 두 사람
사이에는 가족, 권력, 애정, 경쟁과 빚 같은 관계가 동시에 존재할 수 있고 감정과 신뢰는 양방향이
같지 않을 수 있다.

- 노드는 안정적인 등장인물 식별자를 가진다.
- 관계 간선은 시작 인물, 도착 인물, 관계 종류와 사용자에게 보일 설명을 가진다.
- 감정·신뢰·적대·의존·권력처럼 비대칭인 관계는 방향성 간선으로 저장한다.
- 가족처럼 대칭적인 사실은 상호 관계로 표시할 수 있다.
- 관계 상태는 효력이 시작되고 끝나는 사건을 참조한다.
- 관계 변화는 원인이 된 사건을 참조해야 한다.
- 실선은 원문에 직접 명시된 관계, 점선은 분석 중 추론된 관계처럼 화면에서 구분한다.
- 사용자는 간선을 눌러 원문 근거를 확인하고 정본 여부를 결정한다.

관계 그래프는 표시용 그림에 그치지 않는다. 사건 없이 갑자기 신뢰가 회복되거나, 현재 관계와
맞지 않는 태도가 등장하는 문제를 평가하는 입력으로 사용한다.

## 정본 명제와 진실의 층위

소설의 상충하는 문장은 모두 설정 오류가 아니다. 객관적 사실과 인물의 믿음, 소문, 거짓말,
화자의 주장과 작가가 의도적으로 감춘 진실을 분리해야 한다.

정본 명제는 주체, 속성 또는 관계, 값, 유효한 사건 구간과 진실의 층위를 가진다. 진실의 층위는
객관적 사실, 특정 인물의 믿음, 소문, 의도적 기만, 화자의 주장과 미정으로 나눈다. 필요하면 해당
믿음을 가진 인물과 독자에게 진실이 공개되는 사건도 기록한다.

시간 구간은 상태 변화를 모순과 구분한다. 어떤 인물이 계약 전에는 마법을 쓸 수 없고 계약 뒤에는
쓸 수 있는 것은 두 명제가 서로 다른 유효 구간을 가지는 변화이지 설정 오류가 아니다.

## 정본화 인터뷰

인터뷰는 AI가 임의로 선택해서는 안 되는 부분을 사용자 결정으로 바꾸는 단계다. 질문은 발견된
문제와 원문 근거에서만 생성하며, 선택지마다 그 판단을 뒷받침한 출처를 함께 보여준다.

질문은 다음 유형을 지원한다.

- 같은 이름이나 별칭이 동일 인물·장소를 뜻하는지 확인
- 서로 충돌하는 사실 중 정본 선택
- 사건의 시간 순서 결정
- 관계의 방향, 의미와 변화 원인 확인
- 객관적 사실, 믿음, 소문, 거짓말 또는 의도적 미스터리로 분류
- 생성에 필요한 누락 정보 입력
- 의도적인 모호성을 그대로 유지할지 확인

질문은 생성 영향도에 따라 필수, 중요, 선택으로 나눈다. 동일 인물 여부, 핵심 세계 규칙 충돌,
주요 사건 순서, 주인공 목표, 주요 인물 생존 여부와 결말 의도는 필수 후보가 된다. 사소한 외형
차이와 본문에 등장하지 않을 배경 정보는 선택 질문으로 남길 수 있다.

사용자는 모든 빈칸을 강제로 확정하지 않아도 된다. 아직 미정인 내용은 단정 금지, 의도적 모호성
유지 또는 후속 설계 단계에서 제안 허용 중 하나의 생성 규칙을 갖는다.

답변은 분석 초안을 조용히 덮어쓰지 않는다. 어떤 질문에 어떤 선택을 했으며 어떤 정본 명제를
확정·거부·수정하거나 어떤 개체를 병합했는지 결정 기록으로 남긴다. 답변을 적용한 뒤 영향받은
인물, 사건, 관계와 명제만 다시 검사해 후속 질문을 만든다.

## 승인된 이야기 정본

정본화 인터뷰의 최종 산출물은 사용자가 확인한 이야기 정본이다. 여기에는 세계관, 인물,
관계 그래프, 사건, 정본 명제, 명시적으로 남긴 미정 내용과 사용자 결정 기록이 포함된다.

분석 초안은 AI의 관측이고 이야기 정본은 사용자의 창작 계약이다. 생성기는 원고를 고치기 어렵다는
이유로 이야기 정본을 바꿀 수 없다. 사용자가 정본을 수정하면 분석·인터뷰·컴파일과 승인을 다시
거친다.

## 반복 개선

정본화가 끝난 뒤의 관제실 흐름은 다른 Harnest 템플릿과 같다.

- 사용자는 생성·채점 모델, 평가 기준, 보호 장치와 호출 예산을 확인하고 승인한다.
- 원샷 원고 또는 기존 초고를 같은 절차로 채점해 기준선을 기록한다.
- Generator는 공개된 실패 근거만 보고 수정 전략과 대상을 먼저 선언한다.
- 후보는 한 장 또는 연결된 소수 장면만 원자적으로 수정하고 나머지 원고는 그대로 보존한다.
- 장 누락, 빈 장, 구조 오류와 분량처럼 코드로 확인할 수 있는 조건만 결정적 gate로 검사한다.
- 설정·관계·시간선의 비공개 질문은 매 라운드 집계 점수만 가드 비퇴보에 사용한다.
- 인물 입체성, 인물 아크, 설정 정합성, 사건 인과성, 장면 기능과 문체·시점 유지를 분리해 채점한다.
- gate를 통과하고 가드가 허용 범위에서 퇴보하지 않으며 종합 점수가 엄격히 높을 때만 채택한다.
- 동점은 기존 원고를 유지하고 홀드아웃은 시작과 종료 시점에만 평가한다.
- 각 라운드와 상태 전이를 체크포인트로 저장해 일시정지와 재개를 지원한다.

## 시스템 경계

- 파일 추출, 분석, 모델 호출과 체크포인트는 기본적으로 브라우저 안에서 처리한다.
- 원고와 설정집을 자동으로 Harnest 서버에 업로드하지 않는다.
- 사용자가 명시적으로 결과 저장을 선택한 경우만 기존 저장 경로를 사용한다.
- 페이지와 루프 엔진에는 소설 템플릿 식별자를 검사하는 분기를 추가하지 않는다.
- 문서 분석, 동적 정본화 인터뷰와 정본 적용은 템플릿 등록 인터페이스의 범용 선택 기능으로
  제공한다.
- 이야기 정본 지문과 평가 질문·루브릭 버전을 Evaluation Pack에 결속한다.
- 비공개 가드의 질문·판정 근거와 홀드아웃 신호는 Generator에 전달하지 않는다.

## 첫 구현 범위

첫 백엔드 구현은 다음 기반을 만든다.

1. 출처, 세계관, 등장인물, 관계 그래프, 사건, 정본 명제와 분석 문제의 버전형 스키마
2. 안정적인 식별자와 원문 근거 참조의 무결성 검사
3. 분석 문제에서 범용 정본화 질문을 만드는 결정적 변환
4. 사용자 답변을 결정 기록과 이야기 정본으로 적용하는 로직
5. 필수 질문 미응답, 잘못된 선택지, 끊어진 그래프·사건·근거 참조를 거부하는 테스트
6. 같은 입력과 답변에서 같은 정본 지문을 만드는 결정적 다이제스트

LLM 분석 프롬프트, 대용량 문서 분할, 웹 인터뷰 화면과 원고 생성·채점은 이 기반 위에 후속으로
구현한다.
