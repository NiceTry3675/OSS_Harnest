운영체제 — 프로세스, 스케줄링, 동기화, 메모리 관리

1. 프로세스와 스레드

프로세스는 실행 중인 프로그램이며 자신만의 주소공간, 코드, 데이터, 힙, 스택을 갖는다. 프로세스 제어 블록(PCB)에는 프로세스 ID, 상태, 프로그램 카운터, 레지스터 값, 메모리 정보, 열린 파일 목록이 저장된다. 프로세스 상태는 생성, 준비, 실행, 대기, 종료의 다섯 가지로 나뉘며, 준비 상태와 대기 상태는 다르다 — 준비는 CPU만 있으면 즉시 실행 가능한 상태이고, 대기는 I/O 완료 같은 외부 사건을 기다리는 상태다.

스레드는 프로세스 내부의 실행 흐름 단위로, 같은 프로세스의 스레드끼리 코드·데이터·힙을 공유하지만 스택과 레지스터는 각자 갖는다. 그래서 스레드 간 통신은 프로세스 간 통신보다 빠르지만, 공유 자원에 대한 동기화 문제가 발생한다. 컨텍스트 스위칭 비용도 스레드 쪽이 낮은데, 주소공간을 바꿀 필요가 없어 TLB를 비우지 않아도 되기 때문이다. 반대로 한 스레드가 잘못된 메모리 접근으로 죽으면 프로세스 전체가 죽을 수 있다는 것이 프로세스 격리와의 차이다.

사용자 수준 스레드는 커널이 존재를 모르므로 스위칭이 빠르지만, 한 스레드가 블로킹 시스템 콜을 하면 프로세스 전체가 블로킹된다. 커널 수준 스레드는 그 문제가 없는 대신 스위칭 비용이 크다.

2. CPU 스케줄링

스케줄링의 목표는 서로 충돌한다 — 처리량(단위 시간당 완료 작업 수) 최대화, 응답시간 최소화, 공정성 보장이 동시에 만족되지 않는다.

FCFS(First Come First Served)는 도착 순서대로 처리한다. 구현이 간단하지만 호위 효과(convoy effect)가 발생한다 — 긴 작업 하나가 앞에 있으면 뒤의 짧은 작업들이 모두 기다린다. SJF(Shortest Job First)는 평균 대기시간 측면에서 최적임이 증명되어 있으나, 실행 시간을 미리 알 수 없다는 치명적 한계가 있고 긴 작업이 계속 밀리는 기아(starvation)가 발생한다. 기아는 에이징(aging) — 대기 시간이 길어질수록 우선순위를 올려주는 기법 — 으로 완화한다.

라운드 로빈은 각 프로세스에 동일한 시간 할당량(time quantum)을 주고 순환한다. 할당량이 너무 크면 FCFS와 같아지고, 너무 작으면 컨텍스트 스위칭 오버헤드가 지배적이 된다. 일반적으로 할당량은 대부분의 CPU 버스트보다 약간 크게 잡는 것이 좋다.

선점형과 비선점형의 구분이 중요하다. 비선점형은 프로세스가 자발적으로 CPU를 놓을 때까지 뺏지 않으므로 응답성이 나쁘지만 컨텍스트 스위칭이 적다. 실시간 시스템에서 경성(hard) 실시간은 마감을 못 지키면 시스템 실패로 간주하고, 연성(soft) 실시간은 마감을 놓쳐도 품질 저하로만 처리한다.

3. 동기화

임계구역 문제의 해결책은 세 조건을 모두 만족해야 한다: 상호배제(한 번에 하나만 진입), 진행(진입 희망자가 있으면 무한정 미루지 않음), 유한대기(대기 시간에 상한이 있음).

뮤텍스는 소유권 개념이 있어 잠근 스레드만 해제할 수 있다. 세마포어는 정수 카운터이며 소유권이 없어 다른 스레드가 signal을 호출할 수 있다. 이진 세마포어가 뮤텍스와 비슷해 보여도 이 소유권 차이 때문에 용도가 다르다. 카운팅 세마포어는 동시 접근 가능한 자원의 개수를 제한하는 데 쓴다.

스핀락은 대기 중에 CPU를 놓지 않고 계속 확인하는 방식이다. 임계구역이 아주 짧고 멀티코어일 때는 컨텍스트 스위칭 비용보다 싸서 유리하지만, 단일 코어에서는 잠금을 쥔 쪽이 실행될 기회를 뺏으므로 오히려 최악이다.

교착상태(데드락)는 네 조건이 동시에 성립할 때만 발생한다: 상호배제, 점유대기, 비선점, 순환대기. 하나만 깨면 예방된다. 은행원 알고리즘은 예방이 아니라 회피 기법으로, 자원 할당 요청이 들어올 때 안전 상태가 유지되는지 미리 검사해 안전하지 않으면 요청을 거절한다. 이 알고리즘은 프로세스가 최대 자원 요구량을 미리 선언해야 한다는 비현실적 전제가 필요하다. 기아와 교착상태는 다르다 — 교착은 서로가 서로를 영원히 기다리는 상태이고, 기아는 다른 프로세스가 계속 우선되어 자원을 못 받는 상태로, 교착이 없어도 기아는 발생한다.

4. 메모리 관리

연속 할당에서는 외부 단편화가 발생한다 — 빈 공간의 총합은 충분한데 연속된 큰 덩어리가 없는 상황이다. 페이징은 고정 크기 페이지로 나누어 외부 단편화를 없애지만, 마지막 페이지가 다 안 채워지는 내부 단편화가 생긴다. 세그멘테이션은 논리적 단위로 나누어 공유와 보호가 자연스럽지만 크기가 제각각이라 외부 단편화가 다시 생긴다.

페이지 테이블이 커지는 문제는 다단계 페이지 테이블, 해시 페이지 테이블, 역페이지 테이블로 해결한다. 역페이지 테이블은 물리 프레임마다 하나의 항목만 두므로 테이블 크기가 물리 메모리에 비례해 작아지지만, 검색이 느리고 공유 메모리 구현이 어렵다는 대가가 있다.

TLB는 주소 변환 결과를 캐싱하는 하드웨어다. TLB 미스는 변환 정보가 캐시에 없다는 뜻일 뿐, 페이지가 물리 메모리에 없다는 뜻이 아니다 — 페이지 테이블에는 있는데 TLB에만 없는 경우가 흔하므로 TLB 미스와 페이지 폴트는 다르다.

요구 페이징은 실제로 참조될 때만 페이지를 올린다. 페이지 폴트가 나면 디스크에서 읽어오는데, 이 비용이 메모리 접근보다 수만 배 크므로 폴트율이 조금만 올라가도 실효 접근 시간이 급격히 나빠진다.

페이지 교체 알고리즘 중 FIFO는 구현이 쉽지만 벨레이디의 이상현상 — 프레임 수를 늘렸는데 페이지 폴트가 오히려 증가하는 현상 — 이 발생할 수 있다. LRU와 최적(OPT) 알고리즘은 스택 알고리즘에 속해 이 현상이 발생하지 않는다. LRU의 정확한 구현은 비용이 커서 실제로는 참조 비트를 이용한 클럭(2차 기회) 알고리즘으로 근사한다.

스래싱은 프로세스가 워킹셋만큼의 프레임을 확보하지 못해 페이지 폴트가 폭증하고 CPU 이용률이 급락하는 현상이다. 이때 운영체제가 CPU 이용률이 낮다고 판단해 다중 프로그래밍 정도를 더 높이면 상황이 더 나빠지는 악순환이 생긴다. 워킹셋 모델이나 페이지 폴트 빈도(PFF) 기반 프레임 할당 조정으로 완화한다.
