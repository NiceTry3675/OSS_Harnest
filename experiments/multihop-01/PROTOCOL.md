# 멀티홉 실측 01 — 프로토콜 (동결)

작성: 2026-08-25. 이 문서는 실행 전 동결한다. 정정은 사유·절대 날짜와 함께 추가 기록으로만.

## 질문

AI 케이스 초안 생성에 "서로 다른 이슈의 사실 2개를 종합해야 답할 수 있어야 한다"는
멀티홉 요구를 넣으면, **무문서 정답률**(문서 없이 responder가 맞히는 비율)이
단일 사실 회수형 초안보다 실제로 낮아지는가?

동기: delta-01 큐레이션에서 무문서 정답률 48.8%가 실측됐다(케이스가 너무 쉬움).
멀티홉 요구는 검증 호출 없이 프롬프트만으로 "너무 쉬움" 축을 공격하는 후보 설계다
(제품 도입 논의: 멀티홉 프롬프트 + 난이도 슬라이더 + 근거 인용 표시, 자동 검증 없음).

## 재료·모델

- 원료: delta-01 `cases2.json`의 **가시 세트 35케이스**(Hermes Agent 이슈 Q&A 로그)를
  delta-01 `material_of`와 같은 형식으로 이어붙인 텍스트. 홀드아웃 21케이스는 쓰지 않는다.
- 모델: `gemini-3.7-flash` (Vertex, 서비스 계정). 생성 temp 0.7, 평가자 temp 0.0 —
  delta-01 §4 동결 디코딩과 동일.
- responder·grader 프롬프트: delta-01 harness.py §4 v1을 **그대로 복사**해 동결
  (무문서 프로브: doc 블록 없이 responder 호출).

## 조건 (arm)

각 arm은 생성 호출 1회로 15케이스 초안(질문+동결 정답)을 JSON으로 받는다.

- **A (단일 회수형, 대조군)**: 원료에 근거한 질문·정답을 요구하는 기본 프롬프트.
- **B (멀티홉 k=2)**: A + "서로 다른 이슈의 사실 2개를 종합해야만 답할 수 있어야 한다.
  각 케이스에 두 이슈에서 그대로 복사한 근거 인용 2개를 포함하라."

## 측정

1. **무문서 정답률** (주 지표): 각 케이스를 responder에 문서 없이 답하게 하고
   grader가 동결 정답과 대조(0 / 0.5 / 1). arm별 평균 점수와 만점 비율을 비교한다.
2. **근거 실존율** (B만, 부 지표): 인용 2개가 공백 정규화 후 원료의 실제 부분 문자열인지,
   그리고 서로 다른 이슈 섹션에서 왔는지 — 모델 호출 없는 로컬 검증. 제품에서
   "보여주기만" 하는 인용의 신뢰도를 가늠하는 참고 지표.

판정 기준(사전 선언): B의 무문서 평균 점수가 A보다 **10점(0.1) 이상** 낮으면
"효과 있음", 그 미만이면 "효과 불충분 — 제품에 무문서 프로브 필터 도입을 재검토".
표본 15/arm은 작으므로 경향 판단용이며 정밀 백분율을 주장하지 않는다.

## 개정 1 (2026-08-25, A·B 실행 후)

B 실측에서 모델이 "두 사실 종합"을 **복합 질문**(독립된 두 질문을 and로 병렬 연결)으로
구현하는 실패 모드가 관찰됐다. 복합 질문은 절반만 일반지식으로 맞혀도 grader가 0.5를
주므로 무문서 0점 비율이 0%로 무너진다(A 33% → B 0%). 이를 분리 측정하기 위해
**arm C**를 추가한다: B + "질문은 하나여야 하고 답은 짧은 사실 하나여야 한다.
두 질문을 and로 잇는 복합 질문 금지. 두 사실이 모두 있어야만 답이 도출되어야 하며,
한 사실만으로 답할 수 있으면 무효." A·B 결과는 변경하지 않는다(캐시 유지).

## 비용

생성 2회 + responder 30회 + grader 30회 = 62회 (flash, 캐시 재사용 가능).
캐시는 `runs/cache/`(커밋 제외), 결과는 `runs/`와 `RESULT.md`에 기록한다.
